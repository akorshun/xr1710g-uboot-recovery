# XR1710G: замена загрузчика на U-Boot с HTTP-рекавери

Прошивка загрузчика на XR1710G (Airoha AN7581, он же Gemtek/econet `xr1710g-ubi`)
сборкой **[YYH2913/http-uboot](https://github.com/YYH2913/http-uboot)** (релиз
`xr1710g_260805`): 10GbE, веб-рекавери со встроенным DHCP и выбором раскладки
UBI, автоматический вход в рекавери при неудачной загрузке.

Всё делается **из работающей системы одной командой**, без UART, TFTP и кнопок.
Проверено на XR1710G с iStoreOS `v1.4.0 r0+1-99598e539d` (ядро 6.18.41),
который приехал со сторонним загрузчиком `U-Boot 2026.07-xr1710g-wiro-recovery`.

## Как это работает

Слот `chainloader` (1 МиБ по смещению `0x600000`) в системе закрыт на запись:
в `/sys/class/mtd/mtd1/flags` нет бита `MTD_WRITEABLE`, и `dd` отвечает
`Permission denied`. Штатного `kmod-mtd-rw` для таких сборок в фидах нет —
модули ядра публикуются в отдельном репозитории под хеш конфигурации ядра
(здесь `6.18.41~df820d96…`), а его OpenWrt не собирает.

Выручает то, что `vermagic` этих ядер не содержит хеша конфигурации:

```
vermagic=6.18.41 SMP mod_unload aarch64
```

Значит `mtd-rw` из **любой** upstream-сборки того же ядра загружается штатно.
Остаётся вопрос раскладки структур — и он здесь не страшен: `mtd-rw` обращается
к `struct mtd_info` ровно по одному смещению (`flags`, второе поле, смещение 4),
а до него нет ни одного поля, зависящего от конфигурации. Это проверяется
автоматически: `tests/check_module.py` дизассемблирует модуль и падает, если тот
полезет к другим полям.

Дальше всё прямолинейно: скрипт снимает защиту, пишет слот через `mtd write`,
сверяет запись обратным чтением по sha256 и при несовпадении **сам возвращает
резервную копию**, затем выгружает модуль и перезагружает роутер.

## Прошивка

```bash
wget -O /tmp/flash.sh https://raw.githubusercontent.com/akorshun/xr1710g-uboot-recovery/main/flash.sh && sh /tmp/flash.sh
```

Именно в два действия и без `-q`: роутер на столе часто живёт без WAN, и тогда
`wget -qO- … | sh` молча ничего не делает — DNS не отвечает, скачивается 0 байт,
`sh` получает пустой ввод и завершается с кодом 0. Здесь ошибка будет видна.

Скрипту нужен интернет только чтобы скачать образ и, если потребуется, модуль.
Без интернета положите файлы рядом и запускайте локально — с ПК это делается так
(Git Bash, Linux, macOS):

```bash
for f in flash.sh firmware/xr1710g-chainloader-slot.bin firmware/mtd-rw-6.18.41.ko; do ssh root@192.168.50.1 "cat > /tmp/$(basename "$f")" < "$f"; done
```

и затем на роутере `sh /tmp/flash.sh` (файлы из `/tmp` он подхватит сам).

Что делает `flash.sh`:

| Шаг | Подробности |
| --- | --- |
| модель | `econet,xr1710g-ubi` из `/tmp/sysinfo/board_name` или DT |
| слот | раздел `chainloader` ровно 1 МиБ |
| текущий загрузчик | версия U-Boot из дампа слота |
| раскладка UBI | по адресу конца раздела `ubi`: 2.0 / 1.5 / 1.0 |
| образ | размер ≤ 1 МиБ, legacy-заголовок uImage, sha256, наличие HTTP-рекавери |
| резервная копия | `/root/xr1710g-chainloader-<дата>.bin` + sha256 |
| снятие защиты | системный `kmod-mtd-rw`, иначе модуль из репозитория со сверкой `vermagic` |
| запись | `mtd write` + обратное чтение sha256; при несовпадении — автоматический откат |
| окружение | `bootcmd` приводится к значению нового загрузчика (если сохранённое окружение валидно) |
| завершение | `rmmod`, перезагрузка после подтверждения |

Опции: `-i <файл>` свой образ, `-m <файл>` свой `mtd-rw.ko`, `-r <файл>` откат на
копию, `-b` ничего не писать (только проверки, копия и подсказки), `-n` без
перезагрузки, `-y` без вопросов.

Резервную копию стоит забрать на ПК:

```bash
scp root@192.168.50.1:/root/xr1710g-chainloader-*.bin .
```

## Откат

```bash
sh /tmp/flash.sh -r /root/xr1710g-chainloader-<дата>.bin
```

Тот же путь работает и для копии с ПК — просто скопируйте её обратно в `/tmp`.
Если система уже не грузится, остаётся веб-рекавери (см. ниже): в него можно
залить и загрузчик, и прошивку.

## Веб-рекавери нового загрузчика

Адрес всегда `http://192.168.255.1`, DHCP выдаёт ПК `192.168.255.2`, кабель —
в порт 10GbE.

* **Само**: у нового загрузчика `bootcmd=run boot_ubi || http_recovery`, поэтому
  при неудачной загрузке рекавери поднимается без участия человека.
* **Кнопкой**: выключить роутер, включить и, когда замигает индикатор порта
  10GbE, нажать и держать `reset`; отпустить, когда индикатор состояния сменит
  ровный красный на «бегущий» рекавери-режим. Запас по времени большой.

Залить в него что-нибудь с ПК можно скриптами из репозитория — они сами найдут
или скачают образ, проверят sha256 и заголовок, дождутся рекавери и покажут
прогресс:

```bash
sh upload.sh                     # новый загрузчик, цель uboot
```

```powershell
.\upload.ps1 -Target firmware -Layout 2.0 -File .\openwrt-...-sysupgrade.itb
```

Ручной эквивалент:

```bash
curl -X POST --data-binary @xr1710g-chainloader-slot.bin -H 'Content-Type: application/octet-stream' http://192.168.255.1/upload/uboot
```

Раскладка для прошивки выбирается **по DTS заливаемого образа**, а не по текущей:

| Выбор | Раздел | Размер | Конец |
| --- | --- | --- | --- |
| UBI 2.0 | `ubi` | 439 МиБ | `0x1be00000` |
| UBI 1.5 | `ubi1.5` | 473,75 МиБ | `0x1e0c0000` |
| UBI 1.0 | `ubi1.0` | 503 МиБ | `0x1fe00000` |

Ошибка в выборе не ломает загрузчик, но Linux может бесконечно ждать
`/dev/fit0`. Заливка прошивки стирает систему, overlay, пакеты и сохранённое
окружение U-Boot; заводские MAC и EEPROM восстанавливаются из вендорного
региона DSD.

## Что лежит в репозитории

| Файл | Назначение |
| --- | --- |
| `flash.sh` | на роутере: проверки, копия, снятие защиты, запись слота, окружение |
| `upload.sh` | на ПК (Linux/macOS/Git Bash): заливка образа в веб-рекавери |
| `upload.ps1` | то же для Windows PowerShell 5.1+ |
| `firmware/xr1710g-chainloader-slot.bin` | загрузчик из релиза `xr1710g_260805` |
| `firmware/mtd-rw-6.18.41.ko` | модуль снятия защиты MTD для ядер 6.18.41 |
| `tests/run.sh` | 83 проверки на фальшивом роутере и мок-рекавери |
| `tests/check_slot.py` | образ слота: magic, CRC, FIT, наличие рекавери |
| `tests/check_module.py` | модуль: ELF, vermagic, символы, обращения к структуре |

```

afbe8712be475cdbf75375ab1d1b28264e9b0578f1a840b0267d52a3c5783a62  mtd-rw-6.18.41.ko
```

`mtd-rw-6.18.41.ko` взят из официального пакета
`kmod-mtd-rw-6.18.41.2021.02.28~e8776739-r1.apk`
(`downloads.openwrt.org/snapshots/targets/airoha/an7581/kmods/6.18.41-1-1f70d6d135d30ef513a7f9bf11f7c3ec/`),
исходники — [openwrt/packages, `kernel/mtd-rw`](https://github.com/openwrt/packages/tree/master/kernel/mtd-rw)

Скрипт всё равно сверяет `vermagic` модуля с ядром и откажется его загружать при
несовпадении.

## Полезные подробности устройства

* Разделы: `vendor` 6 МиБ, `chainloader` 1 МиБ (`0x600000`), `ubi` `0x1b700000`,
  `reserved_bmt` 66 МиБ. Активного слоя ремаппинга (NMBM/BMT) нет — `reserved_bmt`
  это просто зарезервированная область, поэтому запись через `mtd` идёт напрямую.
* Тома UBI: `fit`, `ubootenv`, `ubootenv2`, `factory`, `rootfs_data`.
* Слот загрузчика — это legacy-uImage-шим с корректными CRC, а по смещению
  `0x2100` лежит FIT со второй ступенью U-Boot. Рекавери проверяет и magic, и
  CRC, так что `u-boot.bin` или `*.itb` в цель `uboot` заливать нельзя.
* `mtd write` стирает блоки только под записываемые данные, поэтому последний
  блок слота сохраняет хвост прежнего загрузчика. Для FIT это безразлично — его
  размер задан в заголовке, — и скрипт сверяет ровно столько байт, сколько в
  образе.
* Сохранённое окружение U-Boot **полностью заменяет** встроенное, поэтому
  `flash.sh` приводит `bootcmd` к значению из нового образа. Если окружение
  пустое (`fw_printenv` пишет `Bad CRC`), скрипт его не трогает: загрузчик
  возьмёт свои значения.
* Сторонний загрузчик `xr1710g-wiro-recovery` игнорирует окружение, записанное
  из Linux: сохранённый env корректен по формуле U-Boot (CRC над `data` при
  `ENV_SIZE=0x4000` с резервной копией), но эта сборка его не принимает — видимо,
  у неё другой `CONFIG_ENV_SIZE` или окружение не резервированное. Поэтому
  «перезагрузиться в рекавери через `bootcmd`» на нём не работает; у новой сборки
  для этого есть штатный `|| http_recovery`.

## Проверено

* **На железе**: `flash.sh` прошёл целиком на живом XR1710G — снятие защиты
  модулем (`mtd-rw: mtd0/mtd1/mtd3: setting writeable flag`, `mtd2` пропущен,
  так как уже был писабельным), запись слота, совпадение суммы обратного чтения,
  правка `bootcmd`, перезагрузка. После неё система поднялась сама, в слоте
  `U-Boot 2026.07-00766-g53b73174c0fc`, MAC-адреса и данные не пострадали,
  защита разделов вернулась (`mtd1=0x0`).
* **В CI**: 83 проверки на фальшивом роутере (подменённые `/proc/mtd`,
  `/sys/class/mtd`, дамп слота, `mtd`, `insmod`, `fw_printenv`/`fw_setenv`,
  `reboot`) и на мок-рекавери, под `dash`, `busybox sh` и `bash`; отдельно
  shellcheck, разбор `upload.ps1` парсером PowerShell, проверка образа слота и
  модуля, сверка образа с ассетом релиза.
